6.4 — Remove FirmId references from OTHER entity configurations

For each of these 9 entities in AppDbContext:

  Notification

  - Any `entity.HasOne(e => e.Firm).WithMany(f => f.<collection>)

  - Any composite index that includes FirmId — replace with an

  - DeletedAt query filters
  - Any non-firm-related foreign keys
  - Indexes on Email, Slug, Phone (the User entity's Slug index

Search Infrastructure for any remaining Firm references:

8.4 — Generate the migration

Once Infrastructure builds, run from the solution root:

    dotnet ef migrations add RemoveFirmsAndSubscriptions \
      --project src/LexCore.Infrastructure \
      --startup-project src/LexCore.API

IMPORTANT: The --startup-project must point at the API project
because AppDbContext's connection string lives in appsettings.

If the command fails because the API project doesn't build —
that's expected. Use this alternate approach:

    dotnet ef migrations add RemoveFirmsAndSubscriptions \
      --project src/LexCore.Infrastructure \
      --context AppDbContext \
      -- --environment Development

If that also fails, create the migration MANUALLY:

    Create file:
    src/LexCore.Infrastructure/Migrations/<Timestamp>_RemoveFirmsAndSubscriptions.cs

With a migration class that:
  - In Up():
      migrationBuilder.DropTable("Subscriptions");
      migrationBuilder.DropTable("Firms");
      Then for each of Case, User, Document, Hearing, Invoice,
      Payment, Chat, AuditLog, Notification tables:
          migrationBuilder.DropIndex("IX_<Table>_FirmId", "<Table>");
          migrationBuilder.DropColumn("FirmId", "<Table>");
  - In Down():
      Can be left empty or throwing NotSupportedException. This
      is a destructive one-way migration; rollback is not
      supported. Add a comment explaining this.

8.5 — Apply the migration

Run:

    dotnet ef database update \
      --project src/LexCore.Infrastructure \
      --startup-project src/LexCore.API

If the startup project doesn't build, apply the migration via
SQL directly: generate the SQL script first:

    dotnet ef migrations script \
      --project src/LexCore.Infrastructure \
      --startup-project src/LexCore.API \
      --output migration.sql

Then pipe it to psql or run it manually in pgAdmin.

8.6 — Verify the database state

Connect to the PostgreSQL database and run:

    \dt

There should be NO Firms table. NO Subscriptions table.

Then:

    \d cases
    \d users
    \d invoices

None of them should have a firm_id column.
